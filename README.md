# abooker

Сервис для поиска, скачивания с торрентов и экономного self-хостинга
аудиокниг. Находишь книгу через Telegram-бота, бот добавляет её в твою
коллекцию и выдаёт RSS-фид, подписываешься на него в любом подкаст-клиенте —
и слушаешь. Главы скачиваются лениво (только когда реально нужны) и
самостоятельно вычищаются из кеша, когда становится мало места.

Под «главой» здесь всегда имеется в виду один аудиофайл раздачи — не
литературная глава. Аудиокнига в торренте — это просто набор файлов с
единственно верным порядком повествования; как именно она разбита на файлы
(по главам, по частям внутри глав, вообще без деления) — не важно.

## Возможности

- **Поиск торрентов** через Jackett — по умолчанию rutracker.org, список
  трекеров расширяется через настройки Jackett, без правок кода abooker.
- **Коллекция** — из результатов поиска или присланной magnet/.torrent/URL
  ссылки бот создаёт публикацию и добавляет её пользователю.
- **RSS-фид** на каждую книгу, совместимый с любым подкаст-клиентом
  (iTunes/Google Play extensions); порядок файлов вычисляется по числам во
  всём их пути внутри торрента (каталоги + имя), а не по алфавиту одной
  только строки имени (см. `files.build_chapter_aliases`).
- **Постраничный список глав в боте** — статус каждой (⬜/⏳ с оценкой
  времени/✅), кнопки «🔥 прогреть» и «🗑 удалить» для каждой главы отдельно.
- **Ленивая раздача** — HTTP-сервер по ссылке из RSS отдаёт файл, если он в
  кеше; если нет — ставит главу (плюс несколько следующих) на закачку и
  держит соединение открытым, пока прогресс скачивания растёт; как только
  прогресс замирает на `DOWNLOAD_STALL_TIMEOUT` секунд — отвечает 503, сама
  закачка при этом продолжается в фоне.
- **Прогрев наперёд** — после отдачи главы N автоматически подкачиваются
  N+1..N+WARMUP_DEPTH.
- **Вытеснение по месту на диске** — как только свободного места становится
  меньше `MIN_FREE_DISK_GB`, глобально (across всех книг) удаляются главы с
  самой старой датой последнего обращения — независимо от того, чья это
  книга и какая у неё сейчас «зона прогрева».
- **CLI** для генерации RSS из локальной папки (исходный режим работы).

## Архитектура

```
abooker-web   — FastAPI: /publications  /rss/{slug}  /file/{slug}/{path}
abooker-bot   — aiogram 3: приём торрентов, /list /status /search, чаты по главам
qbittorrent   — торрент-клиент (lscr.io/linuxserver/qbittorrent)
jackett       — поиск по трекерам, список трекеров настраивается в самом Jackett
```

Данные хранятся в `DATA_DIR/{slug}/`: `publication.json` (для восстановления
после потери БД), `playlist.rss`, `files/` (символические ссылки на файлы,
скачанные qBittorrent — без дублирования на диске). SQLite (`abooker.db`)
хранит статусы файлов, клиентов и события скачивания.

### Жизненный цикл книги: pending_metadata → warming_up → ready

Добавление книги — не одна атомарная операция, а последовательность
наблюдаемых состояний (`Publication.status`), а не что-то, что живёт только
в стеке вызовов на время запроса:

- **`pending_metadata`** — ссылка принята, торрент добавлен в qBittorrent, но
  список файлов ещё не пришёл (актуально для magnet-ссылок: хэш известен
  сразу, а файлы — только после того, как метаданные подтянутся от пиров/DHT,
  см. `torrent.client.wait_for_metadata`). Строка в БД создаётся сразу, до
  того как известны файлы/слаг/название — так процесс переживает падение
  бота посреди ожидания: `cleanup_orphaned_pending()` при старте подчищает
  «осиротевшие» записи в этом статусе. Бот в это время периодически
  обновляет статусное сообщение (прошедшее время + `dht_nodes`/сиды-личи —
  сигнал, реальна ли раздача или сеть просто не пускает P2P-трафик).
- **`warming_up`** — метаданные получены, AudioFile-записи/RSS/
  `publication.json` уже существуют (значит `/rss` и `/file` уже работают),
  но не все из первых `WARMUP_COUNT` глав ещё лежат в кеше.
- **`ready`** — прогрев головы завершён. Статус чисто информационный: ни один
  роут на нём не завязан, отдачу каждого файла решает его собственный
  `AudioFile.status`.

Если метаданные так и не пришли или содержимое не прошло валидацию —
плейсхолдер-запись просто откатывается (удаляется), а не помечается как
«ошибка»: иначе повторная попытка с тем же хэшем раздачи попала бы в
дедупликацию и молча вернула бы «успех» по на самом деле неудачной раздаче.

### Почему `/file/...` держит соединение, а не сразу отвечает 503

При промахе кеша хендлер ставит главу (и несколько следующих) на закачку и
опрашивает прогресс раз в `DOWNLOAD_POLL_INTERVAL` секунд: пока прогресс
растёт — ждём дальше, таймер неподвижности (`DOWNLOAD_STALL_TIMEOUT`)
сбрасывается при каждом продвижении. Если скачивание за это время
завершилось — файл материализуется в кеш и отдаётся тем же запросом; если
прогресс застрял — отвечаем `503` с телом `{"status": "downloading",
"eta_seconds": …}` и `Retry-After`, но саму закачку не отменяем.

Подкачанные в фоне (без единого HTTP-запроса) файлы всё равно переводятся в
`cached` отдельной задачей (`cache.manager.periodic_finalize`, тикает раз в
15 сек) — например, головные главы, которые прогреваются сразу при
добавлении книги, ещё до того, как их кто-то запросит.

### Технический алиас для сортировки и раздачи файлов

Торренты именуют и раскладывают файлы как попало: `Глава 10.mp3` встаёт
перед `Глава 2.mp3` по алфавиту, а нумерация может быть вообще не в имени
файла, а в структуре каталогов (`Книга 1/Глава 1/Отправление (часть 1).mp3`).
`files.build_chapter_aliases()` читает **весь** относительный путь файла
внутри торрента (все каталоги + имя), вытаскивает из него все числа по
порядку, выравнивает каждое нулями (ширина считается отдельно на каждую
позицию кортежа, а не одна на все — так один шумный компонент вроде года
в имени релиза не раздувает отступ для остальных чисел) и склеивает их
через `.` в префикс перед оригинальным именем файла:

```
Книга 1/Глава 1/Отправление (часть 1).mp3  →  01.01.01-Отправление (часть 1).mp3
Книга 1/Глава 1/Засада (часть 2).mp3       →  01.01.02-Засада (часть 2).mp3
Книга 2/Глава 1/Битва в лесу (часть 1).mp3 →  02.01.01-Битва в лесу (часть 1).mp3
```

Этот алиас — не только сортировочный ключ: это буквальное имя файла и в URL
раздачи (`/file/{slug}/{alias}`), и в `DATA_DIR/{slug}/files/`. Оригинальное
имя файла при этом не теряется — просто получает спереди этот префикс,
поэтому папка с уже скачанными главами остаётся пригодной для обычного
оффлайн mp3-плеера (в т.ч. аппаратного): сортировка по имени файла сама по
себе даёт правильный порядок, даже без RSS и приложения-подкастера. Путь
файла *внутри торрента* (для поиска скачанных байт в каталоге qBittorrent)
хранится отдельно в `AudioFile.source_path` — сам файл там никогда не
переименовывается.

## Быстрый старт (локальная разработка)

```bash
make install
cp .env.example .env   # заполнить BOT_TOKEN, JACKETT_KEY и т.д.

make dev-web   # веб-сервер с hot-reload, порт 8000
make dev-bot   # Telegram-бот
make dev       # оба сразу
```

## Docker Compose (всё в контейнерах, для локального теста)

```bash
cp .env.example .env
docker compose up -d
```

`abooker-web` (:8000), `abooker-bot`, `qbittorrent` (WebUI :8080), `jackett` (:9117).

## Развёртывание на VDS

Боевая инстанция — `sl2` / `https://ab.sublayers.net`. `abooker-web` и
`abooker-bot` там работают нативно через systemd (не в Docker — на маленькой
общей машине это ощутимо экономнее), `qbittorrent`+`jackett` — в Docker
(`docker-compose.vds.yml`), раздача идёт через уже существующий на машине
общий nginx-контейнер. Подробности и обоснование архитектуры —
[`deploy/DEPLOY.md`](deploy/DEPLOY.md).

```bash
make vds-deploy      # код + зависимости + рестарт systemd
make vds-up/down/restart/logs/status
make vds-docker-up/down/logs   # qbittorrent + jackett
```

## CLI (генерация RSS из локальной папки)

```bash
uv run abooker -d path/to/audiobook_folder \
    --url=http://my_host/path/to/abooks/ \
    --title="Война и мир" \
    --author="Лев Толстой"
```

| Опция | Описание |
|---|---|
| `-d / --dir` | Путь к папке с аудиофайлами (обязательно) |
| `-u / --url` | Базовый URL для HTTP-раздачи |
| `--rss` | Имя выходного файла (по умолчанию `playlist.rss`) |
| `--title`, `--author`, `--description`, `--image`, `--lang`, `--link` | Метаданные |
| `-S` | Сохранить настройки в `.abooker` родительской папки |
| `--no-local-settings` | Не загружать настройки родительской папки |
| `--verbose` | Отладочный вывод |

## Структура пакета

```
src/abooker/
  cli.py / rss.py / settings.py / files.py  — CLI-ядро + build_chapter_aliases()
  format.py    — fmt_bytes/fmt_duration (используются ботом)
  core/        — config, ORM-модели, БД (+ лёгкие ALTER TABLE миграции), slug
  torrent/     — qbittorrent-api wrapper, create_publication()
  cache/       — warmup, eviction, дисковая квота, финализация фоновых закачек
  web/         — FastAPI app + routes (/publications, /rss, /file)
  bot/         — aiogram 3 handlers (search/list/status/auth/chapters), keyboards
  search/      — Jackett API
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATA_DIR` | `/data` | Каталог хранения публикаций |
| `QB_HOST` / `QB_PORT` | `qbittorrent` / `8080` | qBittorrent WebUI |
| `QB_USER` / `QB_PASS` | `admin` / `adminadmin` | Авторизация qBittorrent |
| `JACKETT_URL` / `JACKETT_KEY` | `http://jackett:9117` / — | Jackett |
| `WARMUP_COUNT` | `2` | Первых N файлов всегда в кеше |
| `WARMUP_DEPTH` | `3` | Кешировать N следующих глав за слушателем |
| `CLIENT_TTL_DAYS` | `14` | Дней без активности до исключения клиента из расчёта прогрева |
| `MIN_FREE_DISK_GB` | `3` | Порог свободного места — ниже него глобально вытесняются самые старые главы |
| `NGINX_ACCEL` | `false` | Отдавать файлы через `X-Accel-Redirect` (нужен nginx с `location /_internal_files/`) |
| `WEB_HOST` / `WEB_PORT` | `0.0.0.0` / `8000` | На чём слушает uvicorn |
| `BOT_TOKEN` / `BOT_ADMIN_IDS` | — | Telegram-бот и список ID администраторов |
| `WEB_BASE_URL` | `http://localhost:8000` | Публичный URL сервера (используется в ссылках RSS) |
| `MAX_FILE_SIZE_GB` / `MIN_AUDIO_RATIO` | `5` / `0.5` | Фильтр раздач при добавлении книги |
| `METADATA_TIMEOUT` | `300` | Сколько секунд ждать метаданные magnet-ссылки (список файлов) от пиров/DHT |
| `METADATA_PROGRESS_INTERVAL` | `15` | Как часто (сек) обновлять статусное сообщение бота при ожидании метаданных |
